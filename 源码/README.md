# 轻宿 · 宿舍减脂与特殊健康饮食助手

面向大学生宿舍场景的减脂应用。核心主张不是"帮你算热量"，而是**"告诉你今天在食堂怎么选、在宿舍怎么练"**。
另有一个完全独立的**特殊健康状况**模块：选择慢病 / 运动术后 / 重症营养病种，查看 JSON 驱动的食谱、食物检索与活动建议。

- 零依赖：只需 Node 18+，**不需要 npm install**
- 手机优先：单手操作、底部四页签
- 内置 DeepSeek Flash 默认配置；模型不可用时自动降级本地科普，页面不显示失败状态

---

## 快速开始

```bash
cd canteen-fit
node server.js
# 打开 http://localhost:3000
```

想换模型或换 key：把 `.env.example` 复制成 `.env` 覆盖默认配置，重启即可。页头会显示 `AI 双助手`。

手机调试：让手机和电脑连同一个 Wi-Fi，用 `http://<电脑内网IP>:3000` 打开。
**注意**：这种情况下浏览器会提示"不安全"，拍照上传仍可用（走 `<input capture>`），但定位等敏感能力不可用。

## 功能与取舍（对应比赛说明书）

| 原始设想 | 处理 | 原因 |
|---|---|---|
| 身高性别体重 → 每日摄入与缺口 | **保留** | 这是底座。用 Mifflin-St Jeor + TDEE，公式算，不交给 AI |
| 目标健康校验、过快减重提醒 | **保留并升级为亮点** | 硬边界：BMI<18.5 直接拒绝、每周减重≤体重1%、热量不低于 BMR×1.1 |
| 导入作息与课表 | **降级** | 不做课表 OCR（十天做不好，错一行全盘错）。改为手动填可用时长 + 连续训练天数 |
| 身体状态 → 动态调缺口与训练 | **保留，全产品最亮的点** | 熬夜困倦缺口×0.6、训练×0.6；疲惫不适缺口×0.4、只做恢复 |
| 内置食堂菜品库 | **改为"个人当日菜品库"** | 全国食堂菜品库是做不完的数据工程；用户每次拍照/打字建立当日菜单，反而更真实 |
| 三餐最优搭配 | **保留，但不用 AI 算** | 穷举 1–3 道菜的组合做加权误差优化。**大模型算数会瞎编，热量必须由代码算** |
| 拍照识别热量 | **保留，且必须可修正** | AI 唯一不可替代的能力：把照片变成结构化数据。识别结果强制人工确认 |
| 多维度饮食打分 | **从 5 维收到 4 项** | 热量 40 / 蛋白 30 / 脂肪 15 / 记录完整度 15，用户一眼看懂 |
| 训练动作 | **改为动作池 + 按日轮换** | 低/中/高三档各 5–6 个动作，按日期做确定性轮换：同一天结果一致，换天就变，不再是固定三套 |
| AI 只会"识别" | **新增 AI 教练对话** | 一句"室友点了炸鸡"就能估算摄入 + 给一句能执行的话 + 解释为什么今天这么练 |
| 页面单调 | **今日 Hero 卡 + 7 天趋势图** | 剩余可吃大数字 + 进度环 + 摄入/目标虚线 + 评分折线 |
| 社交、商城、分享海报 | **删** | 十天做不完，且与评分维度无关 |

### 有意保留的两个"反 AI"设计

1. **数学不交给大模型**：缺口、搭配、打分全部是确定性代码。答辩时这是加分项——"我们知道模型算不准数"。
2. **AI 输出必须可编辑**：识别结果页每个数字都能改，改完才算数。这既是产品诚实，也是应对"识别不准"的唯一办法。

## AI 用在哪（说明书写这段）

| 场景 | 接口 | 输入 | 输出 |
|---|---|---|---|
| 拍餐盘估算热量 | `POST /api/vision` | base64 图片 | 菜品数组（名称/克数/热量/三大营养素/置信度） |
| 打字输入今日菜品 | `POST /api/extract` | 一段中文 | 同上 |
| 减脂运动 AI | `POST /api/chat-sport` | 档案 + 可用时间 + 今日状态 + 问题 | SSE 流式运动科普回复 |
| 膳食健康 AI | `POST /api/chat-diet` | 病种 + 档案 + 三餐 + 热量 + 可选照片 + 问题 | SSE 流式膳食科普回复；`mode=recognize` 返回图片识别 JSON |
| 旧版 AI 教练 | `POST /api/coach` | 一句口语 + 今日预算上下文 | 保留兼容，不再作为主要入口 |

`server.js` 内置 DeepSeek Flash 默认配置（`deepseek-flash`，图片用 `deepseek-v4-flash-vision-exp`），也可以用 `.env` 的 `AI_BASE_URL / AI_API_KEY / AI_MODEL` 覆盖。
两个对话接口使用独立系统提示词；密钥失效、模型报错或余额不足时，会自动降级为本地科普回复，不把错误状态显示到页面。

## 特殊健康状况模块（独立页面，v1.8）

登录后首页先二选一：**减脂模式** 进入原应用；**特殊健康状况** 跳转独立页面。
两者不共享业务状态：健康模块不 import `app.js` / `engine.js`，只读取登录 token，
数据保存在自己的 `localStorage` 命名空间（`canteen-health-*`），不改动原有减脂数据。

### 流程

1. `health.html`：填写性别、年龄、身高、体重、活动量
2. 选择健康情况（单选，分 3 大类，共 14 个已上线病种）：
   - **慢病**：2 型糖尿病、1 型糖尿病、高血压、高血脂、痛风/高尿酸、慢性肾病
   - **运动术后**：ACL 前交叉韧带术后、半月板术后、踝扭伤术后、腰椎损伤
   - **重症营养**：白血病·化疗期、白血病·休养期、实体肿瘤术后、放化疗患者
3. 提交后进入 `health-result.html`，按病种独立展示：
   - 每日参考热量区间（Mifflin-St Jeor × 活动系数 × 病情系数）
   - 带参考份量的三餐食谱
   - 食物检索：🔴 禁食 / 🟡 少吃 / 🟢 推荐，附建议食用量
   - 康复生活指导：适宜运动、运动禁忌、作息、睡眠、饮水、日常起居、情绪管理与复诊提醒
   - 早餐 / 午餐 / 晚餐分餐记录，支持食物文字与拍照；点击对应餐卡可在其下方展开录入
   - 内置早餐 / 午晚餐常用食物快捷多选，自动累加热量；拍照后调用膳食 AI 识别并估算热量，失败时本地模拟填充，可手动修改
   - 每餐提交后按当前病种规范独立评分
   - 全天汇总得分与评价：核查禁忌食物、推荐食材覆盖和热量达标情况
   - 近 7 天每日得分趋势折线图，全部记录、分数、图表数据存在浏览器本地
   - **AI 营养师**对话：结合病种、身体信息、最近三餐和食物照片回答饮食疑问，对话本地缓存
   - **康复生活指导**：按病种独立配置适宜运动、运动禁忌、作息、睡眠、饮水、起居、情绪与复诊提醒
4. 页面固定展示免责文案：
   > 本内容仅为膳食、运动科普参考，不能替代医生、营养师、康复师方案，患有基础疾病请遵从医嘱，本工具不提供诊疗服务。

### 数据驱动与扩展

所有食谱、食物规则、康复生活指导在 `public/health-data.json`，不经过大模型生成，避免模型编造。
新增病种只需两步：

1. 在 `categories` 对应大类里加一个 `status: "active"` 的病种；
2. 在 `conditions` 里加同 id 的详情（`meals` / `foods` / `rehab` / `activity` / `avoidActivity` / `contraindications`）。

`status: "reserved"` 仍会显示为「即将上线」且不可选，便于未来继续扩展；当前 14 个病种全部为 `active`。

### 减脂模块视觉（v1.7）

- 减脂模式恢复清爽浅绿 / 米白 / 浅灰绿配色，与健康模块保持同一套视觉语言

- 保留状态区分：正常 / 熬夜 / 疲惫分别使用绿、低饱和琥珀、低饱和灰绿
- 增加轻量装饰：背景餐盘/叶片线稿、Hero 热量刻度线；不引入图片资源

### 安全边界

- 化疗期明确禁止生冷、未加热、隔夜、不洁食物，水果去皮或蒸熟
- ACL 术后明确避开跳跃、急停、负重深蹲，活动以康复师方案为准
- 白血病化疗期以静养为主，避开剧烈运动和人群密集场所
- 食物照片、分餐记录、分数、趋势、AI 对话都只存在浏览器本地，不上传服务器
- AI 营养师只做膳食营养科普，不做医疗判断、不调整用药，不替代医生/营养师/康复师方案
- 健康模块只做膳食科普，不涉及医疗判断、用药或具体医疗方案，不使用夸大表述

## 视觉与动效（为什么不是"一排白盒子"）

页面用四层节奏代替"卡片等重堆叠"：

1. **小节标题**（`.sec`，带渐变竖条）把页面切成 4–5 段，切断纵向单调
2. **主视觉卡**（`.hero`，蓝色渐变 + 两团光斑 + 46px 大数字）压住首屏
3. **横向滑动卡**（`.hscroll`，scroll-snap）：蛋白缺口 / 今日状态 / 训练量 / 已记录天数
4. **变体卡**：`tint`（浅灰次要）、`dark`（深色反差，用于 AI 推荐搭配）、`flush`（无框）

动效清单（全部 CSS，零依赖）：

- 页签切换时卡片**错峰上浮**（nth-child 延迟 20–310ms）
- Hero 数字**滚动过渡**（从上一个值缓动到新值，不闪回 0）
- 进度环 / 进度条 / 评分环 **width & conic-gradient 过渡**
- 聊天气泡**淡入**，导航选中态**胶囊背景**
- 全部动效在 `prefers-reduced-motion: reduce` 下自动关闭

## 改前端之后必须做的一件事

页面引用的是带内容哈希的文件（`app.<hash>.js` / `styles.<hash>.css`），这样 CDN 不会缓存旧的。

**改了 `public/app.js`、`public/engine.js`、`public/styles.css` 之后，先跑一次：**

```bash
node tools/build.mjs
```

它会重新生成哈希文件并改写 `index.html` 的引用。**不跑这一步，浏览器加载的还是旧文件。**

（这也是之前"改了代码没生效"的根源：文件名没变，CDN 一直吐旧缓存。）
